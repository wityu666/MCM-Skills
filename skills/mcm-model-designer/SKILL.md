# MCM 模型设计

先读 [共享合同](../mcm-suite/references/contracts.md)。用问题合同、真实数据与来源证据设计模型，输出可供 Python／MATLAB 实现的合同；不靠设计文本把未运行结果标为成功。

参照[问题到模型协议](../mcm-modeling-library/references/problem-to-model-protocol.md)消费上游分析；保留现有model.json字段与冻结链，不把旁表的READY_FOR_DESIGN或匹配置信当模型已验证。

## 当前决策与正式冻结

先消费上游的任务/来源、已选路线、前提与首检证据。局部比较/缺项/恢复先给[可行动简报](../mcm-modeling-library/assets/model-selection-brief.md)，回答建议及启动条件、最有用的检查、变化影响；有效内容引用一次，不重新走候选轮次。首检明确执行者、实际输入/操作、判据及失败/预算，已授权且阶段允许的只读数据/环境/解析检查可取证，不能冒充正式求解或结果PASS。正式设计/冻结才展开下列完整接口；无变化不另建冻结ID，实质变化按原链重冻。

## 前置

- 读取 MCM A/B/C 的 `context.json`、年份匹配的 `rules.json`、`contracts/problem.json` 和相关来源。问题合同为 `DRAFT` 时可分析候选，但正式冻结模型前应完成目标、任务和输入边界冻结。
- 按需读取 `contracts/methods.md` 和 `sources/research-notes.md`。结构仍不清楚时交 `$mcm-method-retriever`；只需领域参数或数据时交 `$mcm-data-researcher`，不加载全部方法卡。
- 实质信息不足时先完成不依赖它的模型部分，明确条件性假设和未决项。规则未核验不阻止可逆设计，但不提供正式提交合规结论。

## 行动

1. 核对实际任务输出、上游输入的实体/粒度/时点、变量域、参数、单位及硬要求；对适用任务定义决策变量、目标与约束，不为描述/解释/解析任务生造优化结构。公式、数据字段与代码接口保持同一映射。假设登记依据、适用范围和检验方式，文献参数与团队假设分别标注。
2. 先审上游保留/条件/排除路线的最低输入、识别条件、可表达约束和资源证据；未确认前提保持条件，不因已推荐就采用。比较可实现baseline与最相关候选的收益、解释差异、数据要求、资源成本、验证条件和降级；实际未运行不称胜出。A/B/C 默认类别不能替代问题分析；复现任务先忠实实现用户指定原模型，再单独列扩展。
3. 展示 baseline／候选的简要差异和建议。已有用户授权覆盖路线选择时继续；只有未获授权且会改变目标、数据口径或结果解释的实质选择才请求用户反馈。例行公式化、命名、工具选择和已确认路线不机械多次审批。
4. 先设计一个能改变路线的前提/收益检查，按已有小例、可识别性推导或正确切分试算设置标准、预算与失败动作；这不替代最终verification_plan。主模型增加输出需明确下游产物/字段、单位、时间与不确定性接口；多输出不能塞成一个含混评分。明确定义主模型：方程、目标函数、变量域、初边值、约束容差、估计或求解步骤、参数来源、停止条件、输出格式及资源预算。不适用的目标/约束/切分字段说明理由，不能留空冒充完整；解析结果给推导及人工验算依据。涉及随机过程时声明 seed、重复或不确定性口径；确定性模型不为形式完整强加随机实验。
5. 在 `verification_plan` 中按风险预声明检查对象、方法、阈值和失败动作。可采用单位/守恒/边界、小实例手算或枚举、独立目标与约束重算、样本外验证、时间/分组切分、残差、敏感性、网格收敛或多 seed。选择真正能发现当前错误的检查，不把同算法重复运行当作独立正确性证据，不强制统一双轮方案。
6. 每个重要结论说明需要的运行证据及失效情景；拟强调的创新或改进应可证伪，未有结果前保持候选。为数据不足、求解失败、超时、不稳定或不优于 baseline 设置回退触发器和最晚切换条件。

## 输出与退出

以下正式输出用于模型设计/冻结交接。局部咨询只引用已有合同/相关字段、当前缺口与下一动作，不默认重建文件；正式接口不可由简报代替。

- `contracts/model.json`：按共享合同填写 `status=DRAFT|FROZEN|STALE`、`freeze_id`、当前 `problem_sha256`、`assumptions`、`models`、`verification_plan`、`decisions` 和 `fallback`；模型到任务的覆盖与采用路线明确。
- `contracts/model-notes.md`：必要公式、符号与数据映射、路线差异、资源预算、条件性未决项、降级和论文应披露的限制。仅保存 JSON 无法清楚表达的推导，不重复整份合同。
- 交接给 `$mcm-python-coder` 或 `$mcm-matlab-coder`：冻结版本、源码接口、配置、预期结果和验收要求。实现语言遵从用户选择与可用环境。

模型目标和公式一致、关键输入可获得或已明确为情景参数、验收条件可执行时设为 `FROZEN`。若任务要求唯一核心参数，而现有观测无法识别，受影响合同保持 `DRAFT`；矛盾约束或尚待用户决定的实质路线也按受影响范围保留未决项。可识别组合、可行参数集合或不可识别性诊断可以作为独立输出冻结，前提是任务验收及下游接口明确接受其范围，并保留不确定性和限制，不能包装成唯一真实参数。例如温度观测仅识别降温率 `k/C` 时，可冻结比值估计与等价参数集合，不能分别宣称识别 `k`、`C`；后续只依赖该比值的预测可继续，依赖二者独立值的任务仍待补充观测或有依据的条件。给出最小补充动作和可继续的独立部分。冻结设计不表示运行或结果已通过验证。

## 变更与失效

问题合同 SHA-256 不匹配时先核对任务变化。改变假设、模型、数据来源、参数、求解配置或验证标准需重新冻结，通知编码、结果复核和论文模块按共享合同使旧证据失效；不能为让既有结果通过而事后放宽阈值。

## 模型知识到冻结合同

可以按需调用 `$mcm-modeling-library` 和选中家族建立公式/验证设计，在本合同中保留相关卡ID。继续以本题变量、单位、初边值、目标与约束为准，不为知识库另造第二套冻结状态。把可进入模型的数据、仅背景解释的数据及排除来源分别写入题设要求与模型输入映射；卡的库接口与推荐实现都需在实际环境核验。

## 模型到行文的交接

在现有模型说明中保存选择理由与推导脉络：题设对象/观测/约束为什么需要这个模型，基础方法哪里不足，新增项或变量如何解决，关键公式如何服务输出，以及哪些证据才足以支持预期结论。假设给出依据、作用和受影响结论，避免只写“简化问题”。解析、优化、统计或仿真任务按实际数学对象说明，不为统一章节生造目标函数、随机seed或实验。

候选收益和待执行检查保持未来/条件措辞；普通可靠baseline也可形成完整论文答案，不为了行文亮点把候选升级为PROVEN。内部合同与贡献状态继续保留。正文组织需要时按需调用[$mcm-modeling-paper-writing](../mcm-modeling-paper-writing/SKILL.md)，行文改变数学解释时回到本模型合同。
