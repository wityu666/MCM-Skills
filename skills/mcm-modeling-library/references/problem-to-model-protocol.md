# 从题目到可实现模型

用于拆题、方法比较及交接，不另建冻结链。优先沿用现有问题/模型合同；小任务可在一个简报里完成下列判断，只有跨阶段或多人协作需要机器交接时才使用[可选分析旁表](../assets/task-method-analysis.json)。旁表的READY_FOR_DESIGN只表示有条件进入设计，不表示模型、代码或结果已验证。

## 默认交付与按需展开

默认先给一份当前范围的[可行动简报](../assets/model-selection-brief.md)：先呈现建议/条件、题面任务与关键输入、下一步检查和失败/切换动作。通常可压成一页式概览，但无固定字数、页数、表格或候选数量；关键证据、识别/时点/硬约束和未决风险不能为缩短而删掉。复杂推导和候选细表放在需要的任务后，别先输出流程说明再让用户寻找结论。

按请求选深度：只拆一问/比较方法时，回答本次决策并引用现有来源；正式问题/模型交接或冻结时，完整保留原合同。不要同时复制旁表、模式工作表、问题合同、模型合同的同一事实；源合同/数据各维护一处，其他位置引用实际版本和必要字段。已有合同只在有变化时改相应字段，使用短的“变化—影响任务—需重验”说明；没有变化不新建版本或无故重做全部阶段。

先查现有有效证据。相关卡按当前关键疑问渐进读取：定位后读必要卡/家族，已经确认的前提不重复检索；新疑问再扩展。检索数量少本身不是目标，遇到风险不能省掉必要卡。没有合理新增价值时保留已授权路线，不为模板填候选。

首个检查写到可行动：谁做、读哪些已存在字段/关系、如何判、失败怎样切换、实际预算是什么。把候选缺输入、不可执行和检查失败分开；没有输入时先提出最小补充动作，不给一个现在根本跑不了的“验证模型”命令。多项未知时优先核能改变方法族/可行性且获取成本相称的项；可用一个解析反例排除的方法，不先做昂贵拟合。

若用户已授权且当前规则/阶段允许，可执行只读的数据/单位/信息时点/环境或解析结构微检查，并记录输入版本、方法/命令、真实发现与范围。它不等于正式模型求解、反事实检验或结果PASS；实际建模/生产编码继续走上层冻结与复核门。检查发现错误时修复/补输入仍按授权和版本链处理，不手改原件、静默丢冲突行或自动放松条件。

## 1. 先确认要回答的量

从当前题面提取“对象—动作—输出—条件”，附页/段/小问/附件字段位置。原文要求、可复核推断、建模假设、团队选择和未知项分开；算出来的量写明推导来源。背景中的例子不是自动新增任务，“考虑某因素”也不自动要求再加一个模型。

按可独立验收的输出拆分，不按句子、模型名或固定三问拆。一个小问的预测与配置可能是两个子任务；同一输出的清洗、求参和求解通常是实现步骤，不必每项另造题目。解释、证明、建议或memo可以按证据人工验收，不必为它们虚构数值评分。

| 实际要求 | 先判清的对象 | 容易误配的路线 |
|---|---|---|
| 分析/研究/评价 | 描述现状、诊断模型、估计参数，还是按偏好综合排序 | 看见“评价”就套AHP/TOPSIS/熵权 |
| 估计/反推 | 观测量对应哪个待估量、是否可识别、允许多解否 | 看见“估计”就当未来预测；高拟合等于确定参数 |
| 影响/解释 | 关联、预测贡献、机制推论，还是有识别设计的因果效应 | 回归/SHAP好看就称因果 |
| 预测/分类 | 响应域、预测起点/部署对象、当时可用输入与标签 | 编号当连续响应；事后变量预测过去；无标签改聚类冒充分类答案 |
| 设计/配置/调度 | 只要可行方案、给定目标下优化，还是多目标权衡 | 所有任务都填决策变量/目标；松弛解直接当整数方案 |
| 模拟/演化/控制 | 状态、守恒、事件、反馈及观测/行动时序 | 复杂仿真参数无来源；把观测器当控制律 |

对非优化任务，决策变量/目标函数不适用可以说明；保留实际状态、观测、参数和关系，不删除上层格式要求的字段。建议任务应消费已成立的模型结果，不能凭建议语气再造一个未经题设要求的新目标。

## 2. 数据条件先于模型名称

记录每行/样本代表什么，主键、实体、时间频率/起止、空间尺度、单位、缺失、目标/标签，以及变量何时可获得。文件能读、列名相同、总行数大都不证明数据足够；多个观测来自同一实体时有效独立信息与行数不同。测量值、派生量、文献参数、情景与背景材料分别登记。

查明所需量：已给出并可用、可由已有量推导、需估计但有识别条件、可作为明确情景、确实缺失。无法确认就列unknown和最小补充动作，不偷偷默认分布、单位或连接关系。不得用未来/目标信息构造在预测起点不可得的特征。未知单位或核心标签影响匹配的任务先保留条件分支；只影响增强模型的缺口不阻断已支持的baseline。

## 3. 依赖写产物，先找整体最低路线

每条边说明上游提供哪个产物/字段、含义与单位、粒度、时间口径、版本和不确定性，下游如何消费。预测均值、预测区间、参数后验和情景集合不是可互换输入。后续需要尾部/分布时，单一点预测不自动足够。一个点输入方案可以作为明确的简化baseline，必须说明被忽略风险，并用相称检查评估。

共享输入不等于串行依赖；缺数据的支线不阻断无关任务。遇到循环先辨明共同求解、迭代耦合或实际反馈，并定义信息/状态更新边界，不强行画成虚假的有向无环流程。为用户每项必需交付找整体最低闭环，避免前一问过度优化而后问无实质答案。

## 4. 候选先过前提，再比较收益

需要模型知识时，用`query_models.py --query 关键词`或`--family 家族`定位，再用`--id 真实卡ID --full`读取。检索排序只用于找到资料，不是适配分数；没有命中也不证明无解。模式图谱的pattern_id与细模型库的card_id分开记录，按任务/模型角色建立对应；一张模式卡可涉及多个实际模型，不把两种ID互换。读卡的kind、minimum_data、assumptions、failure_modes、verification及按语言的implementation_evidence，按需查看所选家族SKILL。原资料路径不授权自动访问私库。

先对候选判断：输出能回答任务吗；输入/标签/尺度/时间可满足吗；硬约束和变量域能表示吗；关键参数/机制能识别或明示为情景吗；能做与主张相称的验证吗；实际工具/许可/时间/内存允许吗。硬条件不通过，不能用“先进/热门/潜在高精度”抵消。

给每个保留或排除的候选写具体依据、缺口和证据位置。信息不足用CONDITIONAL或NEEDS_RESEARCH，不给伪精确置信度；已确认不适用用REJECTED，说明哪个条件失败。INDEXED_ONLY仅有名称，不足以设计模型；可先补可靠数学依据。库中理论或参考实现通过只支持其已记录范围，不是本题适配或性能已经通过。

通过前提后选可检查的baseline与有明确新增价值的少量候选。数量服从当前任务，不强制每问三条，也不强迫一个主模式容纳多个不同输出。优势、数据负担、实现代价、解释/主张强度与预期失效同时比较；已授权路线保持，实质目标或解释变更按上层授权处理。

## 5. 先做能改变路线的检查

每个重要候选给一个首个区分检查：检查什么前提/收益，用哪个已有小样本或解析特例，预先怎样判断支持/失败，预算多少，失败后退到什么路线。检查可为数据审计、量纲/可识别性推导、可行性小例或正确切分的试算；不必统一搞多seed/敏感性/交叉验证。无运行时不要写通过、胜出或已证优势。

- 未来预测用实际预测起点的可用输入来比较朴素基准；同主体未来预测隔离时间信息，推广到未见主体/地点时再按相应实体/空间隔离；同样本拟合不能做选型的预测胜出证据。
- 参数反推先查多参数能否被当前观测区分，再谈拟合精度或增加变量。
- 配置/调度先核全部硬约束。连续松弛是界/诊断；如要得到可执行整数方案，需明确恢复方法并重新核约束，不能用放松硬要求凑baseline。
- 评分/排序先检查方向、尺度与偏好是否有意义；报告多维证据也可能足够，不一定聚合。
- 仿真、机理和网络先用数量级、守恒、初边值/连通性等检查；重复运行不会补上缺失的行为或边假设。

把检查结果交给模型设计/编码/复核相应角色。首个检查通过只是减少某风险，最终验收仍按有效合同完成。

## 6. 未决项和交接

最小交接包括：题面任务/交付映射，数据与证据范围，依赖产物，baseline/候选及淘汰理由，首个检查，所缺输入，失败/切换条件，以及交给设计器的真实模型接口。完整选题比较只有在多个真实候选题可用且用户要求时做；优先硬阻断和整体闭环，分数如用仅辅助，不能平均掉缺附件/无验收的风险。

区别全局合规/范围阻断、受影响任务的输入阻断、候选方法的条件缺口。MCM live/practice/reproduce 边界继续由 `mcm-suite` 处理，本协议不绕过它们。可继续部分清楚列出；最小问题问到能改变下一步决策的缺项，常规命名/工具选择不反复问用户。

正式冻结沿用原问题/模型合同和实际SHA；有上层合同的旁表source_contract指向当前问题合同并说明kind=problem，不用模型文件SHA覆盖problem_sha256；普通教学没有问题合同可为空，来源仍登记。旁表仅引用当前问题边界，不是第二套状态。题面、数据可用时点、单位、硬约束、目标或依赖改变时重审受影响匹配，按上层规则使旧模型/证据失效。匹配是可实施候选，设计冻结是明确数学合同，求解/复核才建立当前结果证据。
