# MCM 结果复核

用中文协作，复核证据支持同一冻结结果的完整中英两版论文。复核检查答案、约束和结论；重复运行同一脚本只能说明可复现，不能单独证明模型或实现正确。不强制用 Python 和 MATLAB 分别重写验证实现、固定轮次或全量跨设备重跑。

## 前置与输入

先读 [共享合同](../mcm-suite/references/contracts.md)。核对当前 `context.json`、年匹配 `rules.json`、问题/模型合同，以及 `results/run_manifest.json` 的 `freeze_id`（及可选 `run_id`）与实际输入、代码、配置、环境和输出 SHA-256。仅适用于 MCM A/B/C；`live` 模式遵守当届规则与 AI 披露要求。

需要机器可读结果、复现命令、日志、模型 `verification_plan` 与 `results/numeric_bindings.json`。缺失关键文件、哈希不符或冻结版本不一致时先报告受影响范围；可以继续审核未受影响的单位、公式或已知结果，不能给受影响结论 `PASS`。原冻结结果只读，复核输出另存。

## 按风险选择检查

从题面与模型合同推导验收条件，优先检查摘要数字、最终建议、跨小问传递值和会改变结论的约束。记录选取依据、预先声明的容差与未覆盖范围；不临时放宽阈值来接受已有差异。

| 结果风险 | 有效的独立证据 |
|---|---|
| 优化/调度 | 从决策变量重算目标、全部硬约束与守恒；小实例枚举或上下界核验最优性主张 |
| 预测/分类 | 重新算样本外指标，检查时间/组别/目标泄漏、基准对照和误差分布 |
| 评价/排序 | 独立核算方向、标准化与权重，扰动关键权重/样本检查排名稳定性 |
| 仿真/随机 | 关键统计量重算、多 seed/样本量收敛、区间与极端场景 |
| 机理/几何/网络 | 单位、量纲、初边值、守恒、逐边成本与可手算小例；网格/步长敏感性 |

独立检查不调用主求解函数产生期望值。可使用短检查器、手算、另一算法或局部第二实现；只换代理、语言或函数名不等于独立。按风险组合关键结果重算、可行性/不变量、小样本/边界与鲁棒性；昂贵检查可缩小实例，但明确其对全规模结论的限制。

若复现性本身不确定，按清单在新进程重跑并比较字段与关键值；随机/跨环境差异按事前容差和分布解释。排名、方案选择或可行性改变属于结论差异，不能只用浮点容差消解。

## 真实文件数值追踪

使用 [verify_numeric_bindings.py](scripts/verify_numeric_bindings.py) 从实际 CSV/JSON 结果读取数字并比较登记值：

```bash
python3 /path/to/mcm-result-verifier/scripts/verify_numeric_bindings.py --root /path/to/project --bindings results/numeric_bindings.json --output verification/numeric_binding_review.json
```

每条绑定必须有 `id/file/selector/expected/abs_tol/rel_tol/unit`。CSV 选择器为 `{"row":0,"column":"objective"}`，行号只数数据行；JSON 为 `{"keys":["metrics",0,"value"]}`。源文件、登记文件与报告输出解析真实路径后须位于项目根内，报告不能覆盖来源或登记。脚本记录每个实际源文件的 SHA-256、单位、期望/实测值和 `PASS/FAIL/ERROR`；非全通过返回非零。绑定文件的哈希只识别登记版本，不能替代源文件哈希。

脚本通过仅证明登记数字与所选文件一致。仍要核对源文件与运行清单一致、图表含义/单位和数字绑定的论文陈述，以及上述独立结果证据。

脚本拒绝歧义JSON重复键、文件内非有限数值、不齐CSV记录及错误的已声明版本/冻结标签类型；`freeze_id/run_id`标签不替代真实运行清单核对。极端精度需求超过内部计算资源预算时报告`ERROR`，不缩窄精度或放宽容差使其通过。报告原子写入，只可替换合法同类报告，不覆盖输入/硬链接/符号链接、只读冻结文件或无关已有资料；失败报告与非零退出码必须一并读取，不能消费旧报告。

## 输出、修复与交接

按共享合同写 `verification/result_review.json`，绑定当前 `freeze_id`（有 `run_id` 时一并记录），`manifest_sha256` 必须是当前运行清单文件的真实哈希。用 `checks`、`task_coverage` 与 `unresolved` 列出对象、独立方法、命令/证据路径、容差、结果、限制、未覆盖项与问题影响。

- `PASS`：该报告声明的关键范围已通过独立结果检查与数字追踪，相关结论有证据支持。
- `FAIL`：结果、约束或主张存在已证实差异，记录最小复现与需修复的生产模块。
- `INCOMPLETE`：缺少必要数据、运行环境或验收条件，写明能继续的工作与所需输入。

发现错误先判断属于数据、模型、代码、随机性或展示，交回相应模块修复；不在复核文件里手改生产结果。采用合同中已验证的回退时，重新绑定实际结果与结论。

上游模型、数据、代码、配置、环境或输出变化后，旧报告对受影响范围立即 `STALE`。重算哈希并重新执行相关独立检查；未变化且依赖完整的证据可保留，不机械重做全部小问。

把有效报告、数字追踪报告、独立检查器/证据、当前表图源和保留限制直接交给论文模块。论文仅使用与当前冻结版本及实际哈希对应的有效结果；未核验范围按限制表述，不包装成全面通过。

## 结论强度的写作交接

为摘要、关键图表及最终建议写明“这份检查具体支持什么、尚不支持什么”。训练拟合/同环境复跑、样本外预测、独立正确性、最优性、稳健性和因果识别分开报告。参数扫描如未随机抽样便按实际方法命名；区间标清confidence/prediction/credible或经验范围。MAE/RMSE等指标冲突须先核样本、权重、单位与定义，不靠措辞消解。

通过复核的范围与保留限制一起交给论文角色；未执行检查不能改成已证实优势。[$mcm-modeling-paper-writing](../mcm-modeling-paper-writing/SKILL.md)可据此组织论证，但语言预检不替代本技能的PASS。内部证据ID/状态留在映射表，正文清楚表达数值、对象与边界。
