# 正式比赛默认行文结构

用户指定正式 MCM A–C 比赛采用此结构。它是写作偏好，不是 COMAP 官方模板；新指令或实际题面的专项交付可覆盖相应部分。完整内容已编入本技能集，使用时无需原 Word 文件。

该主线同时用于完整中文与英文两版，按[双语交付约定](bilingual-delivery.md)保持章节功能、模型和结果对应。英文使用[英文大纲](../assets/paper-outline.md)，中文使用[中文大纲](../assets/paper-outline-zh.md)；标题可自然翻译，两版分页不要求相同。

来源：用户提供的 Word 框架，SHA-256 为 `63feb3479c32079c8a1427897d342fed29b6e04fdc97439352afe45b19353be5`，结构核对日期为 2026-10-05。采用其完整目录主线，将正文中重复、错位和缺项整理为下面的一套层级。只提炼章节与论证功能，不复制原稿正文或格式说明。

## 章节顺序与功能

| 顺序 | 英文章节 | 写作功能 |
|---|---|---|
| 前置页 | Summary Sheet，Title，Summary，Keywords | 在一页内概括目标、关键方法机制、真实结果、验证程度与结论条件；结果稳定后定稿 |
| 前置部分 | Contents | 从最终正文标题自动生成，页码与实际 PDF 一致 |
| I | Introduction | 1.1 Problem Background：解释任务背景与必要范围；1.2 Our Work：给出整体解决路线、任务联系与实际贡献 |
| II | Problem Description and Analysis | 2.1 Problem Statement：准确重述目标与交付；2.2 Analysis of Specific Issues：逐问解释目标、输入输出、困难和依赖，避免重复解题结果 |
| III | Basic Assumptions | 列出必要假设及其依据、用途、影响和可检验性，区别题设事实与建模假设 |
| IV | Glossary and Symbols | 4.1 Glossary 解释需要的术语；4.2 Symbols 集中说明符号、含义、单位与取值域，并与公式附近定义一致 |
| V | Models | 按实际任务安排 5.i Analysis and Solution of Task i；每个模型任务按下面四个功能展开 |
| VI | Error Analysis and Sensitivity Analysis | 6.1 Error Analysis 说明误差来源和实际检验；6.2 Sensitivity Analysis 说明扰动设计、重算结果及结论影响 |
| VII | Model Evaluation and Extensions | 7.1 Strengths and Weaknesses：证据支持的优点与具体限制；7.2 Extensions：推广条件、需要的新数据及未执行改进的边界 |
| VIII | Conclusions | 8.1 Conclusions of the Problem：逐问回收答案与建议；8.2 Contributions of the Methods：简要总结方法如何支持这些答案，不再展开公式 |
| IX | References | 在正文使用处引用，核实来源信息，不填造引文 |
| X | Appendices | 按需要设置 Appendix A、B 等，收纳辅助推导或必要细节；没有实质内容时删去空占位并记录不适用 |

一级标题默认采用 I–X，二、三级采用与章号对应的数字编号；若排版工具统一使用阿拉伯章号，保留相同语义顺序。标题样式、层级、编号与目录由同一主稿生成，不手工维持另一份旧目录。

## 每个模型任务的四步

1. **Model Preparation**：说明该问的输入输出、数据整理、参数来源、必要假设和 baseline。公共准备只解释一次，后续问题明确引用。
2. **Model Establishment**：解释选型依据、变量、方程、目标及约束，并交代求解方法、参数估计和计算设置；说明它怎样消费上问输出。
3. **Results**：呈现已经运行并复核的量、单位、图表、场景、比较对象和范围，明确预测、模拟、估计或可行候选的性质。
4. **Analysis of Results**：解释结果怎样回答该问、支持什么判断、哪些条件限制结论，以及如何传给下一问。不得只重复表格数值。

按 `contracts/problem.json` 的实际任务数量生成 2.2.i 和 5.i，不固定三问、四问或四个独立模型。共享模型只建立一次，其他任务引用其必要部分。纯沟通交付不凭空造模型；将其与实际 task ID 对应，可安排为相关任务末尾或独立的题设 memo/letter。

## 后半部分的论证分工

**Error Analysis** 决定数值和模型结论的可信范围。根据任务选择残差、样本外检验、独立重算、约束/守恒检查或数值误差；没有观测真值时不编造预测误差。已经实施的局部验证可留在相应结果分析内，VI 汇总检查方法、重要发现和未决项，避免重复。

**Sensitivity Analysis** 报告改变的输入或参数、变化范围、理由、保持固定的部分、重算的输出和实际影响；没有做过的检查不能写成稳定性结论。小节按实际需要验证的模型组织，不机械要求每个模型使用同一种敏感性实验。

**Model Evaluation and Extensions** 用已检验的事实支持优势，说明哪项数据或假设影响哪项建议；推广说明适用条件和新增验证需求。未来方案写成建议，不写成本次已取得的改进结果。

**Conclusions** 汇总已回答的任务、使用条件和决策意义。方法回顾解释实际贡献，不能替代答案或成为新的算法清单；不在结论中引入新模型、数据或实验。

## 采用结构时的边界

- 沿用上述主线与四步功能，不复制样例年份、题号、团队编号、关键词、旧页码或页眉总页数。
- Summary Sheet、页数、字体、Control Number、匿名和 AI 报告依当前已核验的 `rules.json`；原稿中相互矛盾的字号说明与首页页眉说法不作为规则。保留 MCM A–C 范围和英文正式论文。
- 内容与检验不足时标记草稿或未完成，不靠标题齐全制造完成感；没有验证的优点、误差或推广结论不能补造。
- 默认保留主线。若题面专项材料、共享模型或页数预算要求合并/调整章节，在写作交接中记录结构映射和理由，保持所有实际任务与论证功能覆盖；用户已指定的新安排直接优先，不反复询问常规整合。
- 成稿逐项检查章节层级、实际题数、四步功能、VI/VII/VIII 分工、正文与目录一致性，并清除所有模板编辑提示。结构检查不是数学、结果或最终排版通过。
