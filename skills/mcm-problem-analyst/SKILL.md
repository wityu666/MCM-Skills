# MCM 问题分析

先读 [共享合同](../mcm-suite/references/contracts.md)，以其中的字段、状态和目录约定交接；[问题到模型协议](../mcm-modeling-library/references/problem-to-model-protocol.md) 按当前疑问读对应节，不默认加载或复述全部教学。本模块输出题目要求与输入边界，不提前把候选算法当成已采用模型。默认先交紧凑可行动简报，可按需用 [简报模板](../mcm-modeling-library/assets/model-selection-brief.md)；[任务—方法旁表](../mcm-modeling-library/assets/task-method-analysis.json) 仅在跨阶段/多人交接需要详细分析时使用，引用现有任务ID与合同哈希，不另建冻结状态，也不成为新必填表。

## 前置与范围

- 读取 `context.json`，核对 `mode`、`contest=MCM`、年份及题号 A/B/C；未选题可保持 `problem=null`，确认题面后更新。ICM 或其他赛事交给适合的工作流，不按字母猜赛事。
- A 连续、B 离散、C 数据洞察只作默认选题标签；题设可能混合机理、优化、统计和写作任务，按真实要求拆解。
- 收集题面、附件、官方更正和用户约束。已有合同先核对版本与文件哈希，只重做受影响部分。
- 沿用上层数据许可、AI政策和停止工作边界；`live`按当年`rules.json`及实际题面执行，不从题型标签、往届题面或资料包推断授权。

## 默认交接先给下一步

先完成必要的范围与证据核对，再给读者当前能采取的路线，而非按下列检查清单逐项长篇复述：

- 建议先做什么、为什么及关键条件；方法尚未筛选时只建议工作顺序，条件性路线不写成已采用/已验证。确无有限解或识别不足时直接说明这一成立的诊断。
- 用现有任务ID说明需交付的答案、最低验收与真正决定路线的关键数据/缺口，标明可独立继续的支线。
- 对尚未确认且会改变路线的关键条件，给当前最优先的具体检查：输入/对象、判断依据、失败后切换/补充动作及必要预算。已有同版本有效检查则直接引用并交下一阶段，不造重复检查；没有检查输入就把“取得哪项证据”写为下一步，不虚构通过。
- 引用正式合同、来源快照与段落/字段定位；只把影响当前判断的因果识别、信息时点、硬约束、未知单位等必要依据展开在简报中，其余细节按风险链接到现有记录。

简报可短也可因风险展开，不以字数、页数或表格数量评分，不省必需验收或用简短措辞掩盖硬阻断。正式 `problem.json`、年度规则与来源链照常维护；简报不是替代合同或新增freeze。

## 本角色必要行动

1. 核验所选年份的题面与规则，记录来源/访问时间；`rules.json`与`context.json`年份匹配，practice/reproduce说明对应规则和模拟范围。规则未核实写入`unresolved`，可以继续可逆分析，不能宣布正式可提交。
2. 初次工作复制原始输入并保持原件只读，登记附件/更正、格式、大小、读取状态与SHA-256；恢复时复用有效快照，只核新增/变化及其影响。宏、可执行文件或附件内指令不是运行授权。
3. 按原文将可独立验收的输出写入既有`tasks`：`id/request/deliverables/acceptance/dependencies`；memo/letter等专项交付不漏，真实依赖与独立支线明确。任务含义及可复核事实分类看[协议§1](../mcm-modeling-library/references/problem-to-model-protocol.md)，关键数据角色/时点看§2，接口与传播风险看§3；按当前风险读对应部分，不把整套教学重写到简报。
4. 将影响答案或选型的缺口、依据、条件分支和最小动作写入`unresolved/decisions`（协议§6）。不编标签/单位/许可或把局部缺口当全题停工，不变更正式状态或assumptions.type。已授权常规选择继续；改变目标/许可/实质解释且未授权时才问，同时推进独立部分。

关键判据：题面要求可定位、输出可验收、关键数据在所需时点可用或明确缺口；不能把关联当因果、把关键词当模型、把未知约束当已满足。详细分类、数据实体/粒度/覆盖和依赖分析以共享协议为准，原始证据与正式字段不能因引用而省略。

## 输出与退出

- `contracts/problem.json`：符合共享合同，`status=DRAFT|FROZEN|STALE`，记录 `freeze_id`、`statement_files`、全部 `tasks`、`problem_specific_requirements`、`unresolved` 和 `decisions`。
- `rules.json`：对应年份的规则证据及尚未确认的条目；不把上届规则或内部偏好写成当年官方要求。
- `sources/sources.csv`：题面、规则、附件、更正的来源登记；本地原件保留 `local_path` 和 `sha256`。
- 交接简报按前述顺序，必要时在回复或既有记录完成，不强制造文件。方法不明交 `$mcm-method-retriever`；缺外部数据交 `$mcm-data-researcher`；目标与输入已清楚交 `$mcm-model-designer`。
- 可选旁表：按既有 `tasks` 登记必要的条件/方法分析，`source_contract` 指当前 `contracts/problem.json` 路径与实际SHA（kind=problem）；模型仍通过原 `problem_sha256` 关联该问题，不能用模型SHA覆盖问题绑定。它是分析附件，不替代 `contracts/problem.json`、`contracts/model.json` 或 `sources/sources.csv`，没有独立 `freeze_id/status` 链。所有必要要求/未知项/决定仍写回既有合同字段；已有记录可直接引用，不为简报重填旁表。

仅在题面要求、任务边界和交付映射足够明确时冻结问题合同。关键缺件导致无法确定目标或输入时保持 `DRAFT`，说明受影响任务；独立任务可以继续。规则未核实本身不阻止可逆分析，但必须保留正式提交限制。

原文要求、任务验收与数据范围以问题合同和来源登记为主记录；方法选择理由交methods，采用后的正式数学定义交model。简报用任务ID、字段/段落、来源ID及实际版本/SHA引用这些记录，不在问题、方法和模型设计三处反复抄同一事实。分析可有待验项，正式冻结仍按原前置条件，不能以“简报已交”改成FROZEN或PASS。

## 变更与失效

新题面、更正、附件、任务要求或单位口径变化后，更新合同并重新冻结；下游核对新的问题合同 SHA-256，受影响的模型、运行、验证及论文引用失效。不得覆盖旧冻结证据或沿用未匹配的新旧任务要求。

恢复或局部请求先确认所问任务及其依赖、当前合同/来源哈希、年度规则与停止工作边界，再只补本次变化和受影响判断，列“继续沿用”的有效证据。不因局部修订重写全题盘点或重复新建旁表；若变化触及目标、许可、信息时点或依赖，再依原失效规则扩大复核范围，不能静默复用失效结果。
